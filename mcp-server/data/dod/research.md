# Definition of Done: Research / Spike

Criteria for considering a research task, spike, or investigation complete.

## 1. Documentation
- [ ] A formal Research Report (or Artifact) has been created using the standard `research` template.
- [ ] The report includes a clear Executive Summary.
- [ ] At least two distinct options or approaches have been evaluated (where applicable).

## 2. Analysis Quality
- [ ] Pros, cons, and trade-offs for each option are clearly documented.
- [ ] Findings are cross-referenced and backed by authoritative sources (links provided).
- [ ] Security, performance, and operational impacts are considered for each option.
- [ ] Any project-specific Domain or Layer constraints have been explicitly addressed.

## 3. Outcomes
- [ ] A definitive recommendation is made, accompanied by a clear rationale.
- [ ] Actionable next steps are outlined (e.g., "draft an RFC", "create a proof-of-concept", "update the architecture diagram").
- [ ] If the research is inconclusive, the reasons for this are documented, and follow-up questions/experiments are defined.

## 4. Review
- [ ] The report has been shared with relevant stakeholders (e.g., team lead, domain architect) for feedback.
